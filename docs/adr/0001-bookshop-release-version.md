# Единая версия релиза Bookshop

Для проверки выкладки в Minikube собираем образы frontend и backend с отдельными Docker-тегами, например `0.1.0` и `0.2.0`. При сборке передаём номер через `VERSION` и при необходимости SHA коммита через `REVISION`. Dockerfile задаёт `APP_VERSION` и `APP_REVISION`, а сервис читает их через конфигурацию и публикует в `bookshop_build_info` и стартовом логе. Grafana показывает эти значения для каждого пода. Для сборки без заданной версии поле остаётся пустым.

Пробы отвечают за состояние пода. `/livez` проверяет, что HTTP-сервер отвечает. `/readyz` у backend проверяет доступность PostgreSQL с ограничением по времени, а у frontend — готовность принимать запросы независимо от доступности backend. Доступность каталога целиком проверяет существующая blackbox-проба.

Миграции запускаются отдельным Job Goose. Оператор может запустить его без выкладки frontend или backend. Во время обновления старые и новые поды могут работать одновременно, поэтому миграции для такой выкладки должны сохранять совместимость схемы с обеими версиями.
